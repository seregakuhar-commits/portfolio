## Manual Testing Recommendations

Automated scanning (axe-core: 0 violations / 22 passes; Lighthouse accessibility: 100/100)
found no issues, but a clean automated run does not certify conformance — the criteria
below remain manual by definition. The page is a single-page static site (hero, reveal-
animated content sections, a photo gallery with lazy-loaded images, and two outbound
Telegram links), so the checklist below is scoped to that structure rather than a generic
template.

### Keyboard Navigation
- **SC 2.4.3 Focus Order / SC 2.4.7 Focus Visible** — Tab through the whole page
  (hero → service cards → gallery thumbnails → CTA → Telegram links) and confirm the
  order matches the visual layout and that a visible focus ring appears on every
  interactive element, including the gallery images and the two `.btn-gold` / `.btn-tg`
  links.
- **SC 2.1.2 No Keyboard Trap** — The gallery currently renders as plain `<img>` tiles
  with no JS-driven lightbox, so a trap is unlikely; still verify nothing intercepts
  Tab/Escape once a gallery item receives focus.
- **SC 2.5.3 Label in Name** — Confirm the visible text of the two Telegram buttons
  ("Записаться" / similar) matches their accessible name (no mismatched `aria-label`).

### Screen Reader
- **SC 1.3.1 Info and Relationships / SC 4.1.2 Name, Role, Value** — Walk the page with
  NVDA or VoiceOver and confirm section landmarks/headings announce a logical structure
  (hero → about/services → gallery → CTA), since the markup uses `<section class="...">`
  rather than ARIA landmarks.
- **SC 1.1.1 Non-text Content** — Spot-check that the gallery `alt` text (already present
  and descriptive in Russian, e.g. "Окрашивание волос", "Маникюр крупным планом") reads
  naturally and isn't redundant with adjacent captions.
- **SC 4.1.3 Status Messages** — No dynamic status regions exist on this page (the only
  script is a scroll-triggered `IntersectionObserver` that toggles a `.visible` class);
  confirm it doesn't need an `aria-live` region (it shouldn't, since it's purely visual).

### Visual Inspection
- **SC 1.4.3 Contrast (Minimum) / SC 1.4.11 Non-text Contrast** — axe and Lighthouse both
  passed contrast checks against the current palette, but spot-check the inline SVG icons
  and the gold CTA buttons (`.btn-gold`) against their hero/section backgrounds at actual
  rendered size, since automated contrast checks can miss gradient or image-overlay text.
- **SC 1.4.4 Resize Text / SC 1.4.10 Reflow** — Zoom to 200% and 400% and confirm the
  gallery grid reflows to a single column without horizontal scrolling or clipped text,
  particularly around the `.gallery-grid` and `.about-services` sections.
- **SC 1.4.13 Content on Hover or Focus** — If any hover effects exist on gallery tiles
  or buttons, confirm hover content is dismissible, hoverable, and persistent.

### Cognitive
- **SC 2.4.6 Headings and Labels / SC 3.2.3-3.2.4 Consistent Navigation & Identification**
  — Confirm heading levels descend logically (h1 in hero, h2 per section) and that the
  two outbound CTAs use consistent wording/icons across the page.
- **SC 3.3.1 Error Identification** — Not applicable today (no forms on the page); skip
  and re-test if a booking form is added later.

### Timing & Motion
- **SC 2.2.2 Pause, Stop, Hide / SC 2.3.1 Three Flashes** — The only motion is the
  one-shot `.reveal` fade-in triggered by `IntersectionObserver` on scroll (each element
  is unobserved after first reveal, so it does not loop or flash). Confirm it respects
  `prefers-reduced-motion` — currently there is no media query for it, so users with
  vestibular disorders will see the fade regardless of their OS setting. This is the one
  concrete, testable gap automated scanning cannot flag and is worth fixing.

**Priority for this page:** keyboard focus-order/visibility and the
`prefers-reduced-motion` check above are the highest-value manual checks — everything
else is low-risk given the simple, form-free, lightbox-free structure.
